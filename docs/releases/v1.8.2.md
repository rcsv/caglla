---

## 🔒 セキュリティ修正

### Critical: API認証・認可の欠如

**影響を受けるエンドポイント**:
- `POST /api/itineraries` - 新規旅程作成
- `GET /api/itineraries` - 旅程一覧取得

**問題**:
1. Bearer token検証がない
2. day → trip の所有権確認がない
3. 未認証ユーザーがAPIを呼び出し可能

**修正内容**:
- adminAuth.verifyIdToken による認証実装
- trip.user_id と認証ユーザーのuid照合
- 適切なHTTPステータスコード（401, 403, 404）の返却

## 🔍 影響範囲

### 変更ファイル
- `app/api/itineraries/route.ts`

### 破壊的変更
**あり** - APIクライアントはAuthorizationヘッダーが必須になります

#### Before (v1.8.1以前)
```typescript
// 認証なしで呼び出し可能（脆弱性）
const response = await fetch('/api/itineraries', {
  method: 'POST',
  body: JSON.stringify({ day_id, title, place_id })
})
```

#### After (v1.8.2以降)
```typescript
// Authorizationヘッダーが必須
const token = await user.getIdToken()
const response = await fetch('/api/itineraries', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${token}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({ day_id, title, place_id })
})
```

## 📊 セキュリティリスク評価

### 修正前のリスク
- **重要度**: Critical
- **攻撃可能性**: 高（認証なしで誰でもアクセス可能）
- **影響範囲**: 旅程データの不正作成・閲覧
- **悪用シナリオ**: 
  - 他ユーザーの旅程への不正な追加
  - 旅程データの不正閲覧
  - データベースへの大量書き込み（DoS）

### 修正後のリスク
- **重要度**: Low
- **攻撃可能性**: 低（認証・認可が必須）
- **影響範囲**: 自分の旅程のみアクセス可能
- **残存リスク**: トークンの盗難（別途対策が必要）
