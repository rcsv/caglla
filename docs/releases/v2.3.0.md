# Caglla v2.3.0 リリースノート

**リリース日**: 2025-11-13  
**バージョン**: 2.3.0  
**コードネーム**: "Public Spark"

---

## ✨ ハイライト

- **Public テンプレートモードを刷新**  
  日付なしの日数ベースで旅データを公開できるようになり、公開プラン作成用の UI/バリデーションを全面的に拡充しました。
- **Replica ボタンでワンクリック複製**  
  公開テンプレートから Private Trip へ、旅程・メモ・チェックリストを含めて即座に複製できるようになりました。
- **いいね機能を追加**  
  公開プランにハート＋件数表示を導入し、トグル操作でユーザーからのフィードバックを集められるようにしました。
- **サブスクで公開テンプレートを制御**  
  Backpacker 以上のプランだけがテンプレート作成を選択できるよう、プラン制限の仕組みを強化しました。

---

## 🧭 主な変更点

### Public テンプレート関連
- `CreateTripDialog` / `TripEditor` にテンプレートトグルと日数入力を追加し、テンプレ化時は日付を非必須化。
- 公開テンプレートのデフォルトアクセスを Private から明示的に切り替えられる UI を整備。
- `TripHeroSection` に「テンプレートを使う」ボタンを追加し、レプリカ作成フローを改善。
- テンプレート複製時にメモ・チェックリストも含めてコピーされるよう `planSaveOperations` を拡張。

### いいね機能
- `TripLikeButton` コンポーネントを追加し、Trip 詳細ヒーローと `TripCard` にハート＋件数表示を実装。
- 新 API `GET /api/trip/[tripSlug]/likes` / `POST /api/trip/[tripSlug]/likes` を追加し、冗長カウンタで即時反映。
- `likes_count` / `liked_by_me` フィールドを `Trip` 型に追加し、クライアント全体で扱えるよう統一。

### サブスク制御と UI
- Backpacker 以上だけが公開テンプレートを作成できるよう `PlanLimitChecker` と `PlanLimitsDisplay` を拡張。
- 公開テンプレート制限を i18n に追加し、未対応プランではアップグレード導線を表示。
- Public 作成トグルを利用不可プランで無効化し、警告メッセージを追加。

### テストと品質
- `lib/subscription/__tests__/plan-limits.test.ts` を拡張し、公開テンプレート機能の可否やメッセージ生成を検証。
- Firestore ルールに likes サブコレクションを追加し、クライアントからの直接書き込みを禁止。
- `firestore.indexes.json` に `access_level` / `is_template` / `likes_count` の複合インデックスを追加。

---

## 🛠 技術的な改善

- `lib/core/types/trip.ts` / `lib/core/types/api.ts` に `is_template` / `day_count` / `likes_count` / `liked_by_me` を追加し、型安全性を向上。
- `/api/trip/[tripSlug]/route.ts` / `/api/trips/route.ts` にテンプレート関連フィールドの永続化処理を追加。
- `/api/trip/[tripSlug]/replica/route.ts` を新設し、レプリカ作成をサーバー側で一括処理。
- `MakeAuthenticatedRequest` を用いた likes API 連携で認証処理を統一。

## 📦 影響範囲

- フロントエンド: Trip 作成ダイアログ、Trip 編集モーダル、Trip 詳細ヒーロー、Trip カード、購読プラン UI。

- データモデル: `trips/{tripId}` ドキュメント、`trips/{tripId}/likes` サブコレクション、Firestore インデックス・ルール。
- テスト: `lib/subscription/__tests__/plan-limits.test.ts`.

## 🔄 アップグレード手順

1. `git pull` で最新の `main` を取得してください。
2. Firestore ルールとインデックスをデプロイ (`firebase deploy --only firestore:rules,firestore:indexes`)。
3. いいねサブコレクションが利用できるよう、必要に応じて既存 Public データに `likes_count: 0` をバックフィル。
4. `pnpm lint` / `pnpm test -- lib/subscription/__tests__/plan-limits.test.ts` で検証。
