# Pre-login Content Left Padding Too Large on Mobile

- **Priority**: P1（視認性・UX 低下）
- **URL**: `/`, `/blog`, その他ログイン前ページ
- **Viewport**: width < 640px (mobile)
- **Component**: `app/page.tsx`, `app/blog/page.tsx` のメインコンテンツ（ヒーローセクション、CTA ボタンなど）
- **Epic**: Pre-login responsive layout optimization

## ステータス

- ✅ Fixed (2025-11-11) — `page-rail` のモバイル余白を排除し、前面コンテンツが全幅表示できるよう調整

## 現象

メインコンテンツがモバイル幅でもデスクトップ前提の左余白を維持しており、画面幅の半分近くが空白になる。文章やヒーローイメージが極端に縮まり、視認性が落ちる。

## 再現手順

1. ログアウト状態でトップページにアクセス。
2. ビューポートを 640px 未満に縮める。
3. ヒーローセクションや以下のコンテンツが左に寄らず、余白が大きく残ることを確認する。

## 期待結果

モバイルでは左右の余白が最小限になり、コンテンツが画面全幅を有効活用する。

## 実際の結果

レイアウトが固定されており、デスクトップのグリッドをそのまま縮小したため左側が広く空いている。

## 原因仮説

- コンテナの `padding-left` や `margin-left` がデスクトップサイズで固定されている。
- Tailwind CSS の `lg:pl-*` や `md:ml-*` のみが設定され、モバイル用の `px-4` が適用されていない。
- グリッドレイアウトが `grid-cols-12` などで固定され、左右のカラムが空白になっている。

## 受け入れ基準

- [ ] 640px 未満で左右余白が `px-4`（16px）または `px-6`（24px）に統一される
- [ ] ヒーローイメージとテキストが画面幅の 90% 以上を使用する
- [ ] CTA ボタンの最小タップ領域は 44x44px 以上
- [ ] コンテンツが中央揃えまたは左揃えで視認しやすい配置になる

## アクセシビリティ

- ボタンとリンクのタップ領域は WCAG 2.2 Level AAA 基準（44x44px）を満たす。
- テキストの行間は `leading-relaxed` 以上で可読性を確保。

## メモ

- レスポンシブ用の `px-4` や `max-w` 調整が不足。
- CTA ボタンも画面外側に寄って押しづらい。
- デスクトップ優先のグリッドシステムをモバイルファーストに再設計する必要がある。
- 対応PR: `app/globals.css` にて `@media (max-width: 639px)` の `page-rail` 余白を0にし、装飾ラインも非表示化。
