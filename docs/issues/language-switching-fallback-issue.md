# Issue: 言語切り替えのフォールバック処理による問題

**作成日**: 2025-10-31  
**状態**: 🔴 未解決  
**優先度**: 高  
**関連ファイル**: 
- `lib/i18n/index.ts`
- `lib/utils/language.ts`
- `app/[userSlug]/page.tsx`（プロフィール編集画面）

---

## 📋 概要

プロフィール編集画面で言語を変更しても、フォールバック処理でブラウザの言語設定が優先されるため、いつまで経っても選択した言語が反映されない。

---

## 🐛 問題の詳細

### 現状の問題
1. **プロフィール編集画面での言語変更**
   - ユーザーが言語設定で「English」などを選択
   - 「保存」ボタンを押す
   - しかし、表示される言語が変更されない

2. **フォールバック処理の動作**
   - `t()`関数が言語設定未選択時にブラウザの言語設定を優先
   - プロフィールで設定した言語が反映されない
   - クッキーやブラウザ設定が常に優先される

### 期待される動作
- プロフィールで設定した言語が最優先される
- 言語未設定時のみブラウザ設定をフォールバックとして使用
- 設定した言語が即座に反映される

---

## 🔍 技術的な問題

### 現在の実装（推測）
```typescript
// lib/i18n/index.ts
export function t(key: TranslationKey, lang?: SupportedLanguage): string {
  const language = lang || (typeof window !== 'undefined' ? getUserLanguage() : 'en')
  const dict = dictionaries[language] || en
  return dict[key]
}
```

`getUserLanguage()`がプロフィール設定を優先していない可能性。

---

## 💡 解決方針

### Phase 1: 言語取得の優先順位を明確化

1. **優先順位の定義**
   ```
   1. プロフィール設定の言語（最優先）
   2. クッキー/ローカルストレージの言語設定
   3. ブラウザの言語設定（最後のフォールバック）
   ```

2. **言語取得ロジックの修正**
   - `getUserLanguage()`関数を修正
   - プロフィール設定を最優先で取得
   - 未設定時のみブラウザ設定を使用

### Phase 2: 言語切り替えの即時反映

1. **状態管理の改善**
   - プロフィール保存時に言語設定を即座に反映
   - グローバルな言語状態を更新

2. **UIの改善**
   - 言語変更時の即時プレビュー
   - 保存後の確認メッセージ
