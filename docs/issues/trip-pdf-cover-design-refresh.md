# Trip PDF Cover Design Refresh

- **Priority**: P1（PDFエクスポート体験の品質を大幅に左右）
- **URL**: `/dev-tools/pdf-preview/[tripSlug]`, `/api/trips/[tripSlug]/preview`
- **Component**: `lib/utils/magazine-pdf-template.ts`, `app/dev-tools/pdf-preview/[tripSlug]/page.tsx`
- **Epic**: PDF export experience revamp
- **Milestone**: v3.0 polish

## ステータス

- 🔴 未着手

## 現象

PDFプレビュー（旅のしおり紙面デザイン）のカバーページが、現行アプリのUIトーンとかけ離れた古い印象になっている。太字の手書き風フォント、背景写真に対するオーバーレイ不足、情報配置のバランス欠如などにより「ダサい」と感じる仕上がりになっている。

## 再現手順

1. ログイン済み状態で `http://localhost:3000/dev-tools/pdf-preview/meet-deer-in-nara-jpn` を開く。
2. 「プレビューを再表示」を押して新しいタブでPDFプレビューを開く。
3. 1ページ目（カバー）のタイポグラフィとレイアウトを確認する。

## 期待結果

- ブランドトーンに合致したモダンなタイポグラフィと配色で、旅行冊子として魅力的に見える。
- タイトル、サブタイトル、旅行期間・目的地などのメタ情報が視認性高く整理され、背景写真とのコントラストが確保されている。
- ページ下部のアイコンや装飾要素が適切な余白と一貫したスタイルで配置されている。

## 実際の結果

- タイトルが手書きフォントで極端に大きく、背景写真と馴染まず読みづらい。
- 背景写真にオーバーレイが無いため、テキストのコントラストが不足している。
- 旅行期間や目的地などの情報がフォントサイズ・配置ともに統一感を欠き、視線誘導が弱い。
- 下部のアイコン列がバラバラに並び、余白も狭いため安っぽく見える。

## 原因仮説

- MVP時代のテンプレートをそのまま使用しており、ブランドリニューアルや最近のUIガイドラインに合わせた更新を一度も行っていない。
- フォントや配色がハードコードされており、デザインシステム（TailwindトークンやCSS変数）と連動していない。
- 背景写真前提の可読性テストを行っていないため、暗い/明るい画像で見え方が破綻している。

## 受け入れ基準

- [ ] タイトル・サブタイトル・メタ情報が読みやすいフォントとサイズ階層で再設計されている。
- [ ] 背景写真の明度に依存せず文字コントラストが WCAG 2.1 AA（4.5:1）を満たす。
- [ ] アイコンや装飾を含めた各要素の余白・配置がデザインガイドラインと整合する。
- [ ] 多言語（少なくとも日本語・英語）で文字崩れが起きないことを確認済み。
- [ ] プレビューHTMLとPDF出力の両方で同一レイアウトが再現できる。

## アクセシビリティ

- テキスト読み上げ順序が視覚上の構造と一致するよう `heading` 階層や `aria-label` を見直す必要がある。
- 視認性を確保するため、背景とテキストのコントラストチェックを自動テストに組み込むことを検討。

## 解決アプローチ（初期案）

- デザイン案をFigmaなどで再作成し、フォント・色・余白スケールを確定させる。
- `generateMagazinePdfHtml` 内のスタイルをデザインシステムに準拠したCSSへ置き換え、カラートークンやフォントスタックを整理する。
- 背景写真上に半透明オーバーレイを追加し、画像の明暗に応じた可読性を確保するロジックを導入する。
- ページ下部のアイコン列をFlex/Gridで再配置し、要素間の一貫した間隔とラベル表示（必要なら）を加える。
- UIテストとして複数のサンプル写真で比較スクリーンショットを取得し、レイアウト崩れを手動/自動で確認する。

## メモ

- 既存のデザインは初期コンセプトの雰囲気重視だったが、アプリ全体のトーンが刷新されたため乖離が目立っている。
- 旅行冊子として他者と共有する場面が多いため、第一印象の改善がブランド価値に直結する。
- デザイン刷新後は、PDF生成機能を正式機能として昇格させるロードマップ（`pdf-preview-promote-to-normal-feature.md`）と連動させたい。
