## 📋 概要

**Private / Public に関わらず、特定の人に旅行をシェアする機能**の UI を実装する。

「シェア」とは、公開設定（access_level）の変更ではなく、**一緒に旅行に行く人にデータを開示する**機能である。

---

## 🎯 シェア機能の目的

旅行をシェアすると、シェアされた人は以下が可能になる：

1. **旅行データの閲覧** - すべての情報（日程、旅程、宿泊先など）を閲覧可能
2. **iCal の利用** - iCal 形式でエクスポート・同期可能
3. **PDF の利用** - PDF 形式でエクスポート可能
4. **Checklist の編集** - Checklist の項目を DONE に変更可能
5. **緊急連絡先の共有** - 参加者だけに緊急連絡先を共有可能（将来実装）

## 🔍 既存の実装状況

### バックエンド（既存）

- ✅ **`trip_users` コレクション** - シェアされたユーザーを管理
  - ドキュメントID: `{tripId}_{userId}`
  - フィールド: `trip_id`, `user_id`, `created_at`
- ✅ **Firestore Rules** - `trip_users` に登録されたユーザーは旅行データにアクセス可能
- ✅ **`adminTripUserOperations`** - シェアユーザーの追加・削除・取得機能
- ✅ **`/api/trips/accessible`** - シェアされた旅行を取得する API

### フロントエンド（不足）

- ❌ **シェアボタン** - 旅行詳細ページにシェアボタンがない
- ❌ **シェアモーダル** - ユーザーを招待する UI がない
- ❌ **シェアメンバー表示** - 現在シェアされているメンバーを表示する UI がない
- ❌ **シェアメンバー管理** - メンバーの追加・削除 UI がない

### 既存のコンポーネント（参考）

- ✅ `TripShareSettingsModal` - 公開設定を変更するモーダル（用途が異なる）
- ✅ `ICalPublishModal` - iCal 共有モーダル（参考実装）
- ✅ `TripClientLayout` - 旅行詳細ページのレイアウト

## 🎨 UI/UX 設計

### シェアボタンの配置

**場所**: `TripClientLayout.tsx` の `FloatingTitleBar` の `actions` セクション

**現在のボタン構成**:
1. PDF Export Button
2. iCal Export Button
3. Publish Toggle Switch

**追加するボタン**:
4. **Share Button** (新規) - ユーザーを招待してシェアする

### シェアボタンのデザイン

```tsx
<button
  onClick={handleOpenShareModal}
  className="px-3 py-1.5 text-sm font-medium text-gray-700 bg-white hover:bg-gray-50 border border-gray-300 rounded-md transition-colors flex items-center gap-1.5"
  title="Share trip with others"
>
  <Icon icon="mdi:account-plus" className="w-4 h-4" />
  Share
</button>
```

### シェアボタンを押した時の動作

1. **シェアモーダルを開く**
   - 現在シェアされているメンバー一覧を表示
   - 新しいメンバーを招待するフォームを表示
   - メンバーの削除ボタンを表示（オーナーのみ）

2. **メンバー招待**
   - メールアドレスまたはユーザー名で検索
   - 招待ボタンをクリック
   - `trip_users` コレクションに追加

3. **メンバー削除**
   - メンバー一覧から削除ボタンをクリック
   - `trip_users` コレクションから削除

## 🔄 ユーザーフロー

### フロー1: メンバーを招待

1. ユーザーがシェアボタンをクリック
2. シェアモーダルが開く
3. 現在のメンバー一覧が表示される
4. メールアドレスまたはユーザー名を入力
5. 「招待」ボタンをクリック
6. `POST /api/trips/[tripSlug]/share` を呼び出し
   - リクエスト: `{ email: "user@example.com" }` または `{ userId: "user-id" }`
   - レスポンス: `{ success: true, user: { ... } }`
7. `trip_users` コレクションに追加
8. メンバー一覧が更新される
9. 成功メッセージを表示

### フロー2: メンバーを削除

1. ユーザーがシェアボタンをクリック
2. シェアモーダルが開く
3. 削除したいメンバーの「削除」ボタンをクリック
4. 確認ダイアログを表示
5. 「削除」を確認
6. `DELETE /api/trips/[tripSlug]/share/[userId]` を呼び出し
7. `trip_users` コレクションから削除
8. メンバー一覧が更新される
9. 成功メッセージを表示

### フロー3: シェアされたユーザーの視点

1. シェアされたユーザーがログイン
2. `/home` ページでシェアされた旅行が表示される
3. 旅行をクリックして詳細ページを開く
4. すべての情報（日程、旅程、宿泊先など）を閲覧可能
5. PDF エクスポートボタンが表示される
6. iCal エクスポートボタンが表示される
7. Checklist の項目を DONE に変更可能
8. 緊急連絡先セクションが表示される（将来実装）

## 📝 注意事項

1. **Private/Public の区別**
   - Private でも Public でも、シェア機能は同じように動作する
   - `access_level` はシェア機能とは独立している
   - Public の場合は、シェアメンバー + 誰でも閲覧可能
   - Private の場合は、シェアメンバー + オーナーのみ閲覧可能

2. **権限の階層**
   - **オーナー**: すべての権限（編集、削除、メンバー管理）
   - **シェアメンバー**: 閲覧、iCal、PDF、Checklist 編集、緊急連絡先閲覧

3. **Checklist 編集権限**
   - 既存の API で `trip_users` に登録されたユーザーが編集可能か確認が必要
   - 必要に応じて API を修正

4. **緊急連絡先の実装**
   - 新規機能として実装が必要
   - データモデルの設計が必要
